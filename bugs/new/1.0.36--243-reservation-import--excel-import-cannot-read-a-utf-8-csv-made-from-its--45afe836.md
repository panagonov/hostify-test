# QA-545 · 243-reservation-import — Excel import cannot read a UTF-8 CSV made from its own CSV template (the file is uploaded through /upload/image)

- Версия на приложението: **1.0.36** · Акаунт: QA Automation · Намерен в пуска qa-2026-11-27
- Спек: `tests/e2e/243-reservation-import.spec.ts` — Reservations › Excel import
- Папка на пуска: [test-results](../../test-results)

**Какво се обърка**

Reservations › Excel import (и вторият вход Reservations › Add new ▾ › „Import reservations“ — той води към **същата** страница
Excel import, без своя форма): файл, направен **по собствения CSV template на вноса** (21 колони: listingNickname, guestName,
guestEmail, … checkIn, checkOut, … totalPrice, currency, source, status …), UTF-8 (и с BOM), 3 реда (2 на наша обява и наши гости
@hostify-qa.test, 1 с несъществуваща обява), дати DD.MM.YYYY (форматът по подразбиране) → Save → **Validate**: статус „failed“,
1 грешка на ред 0, поле file: „**The file could not be read; upload an .xlsx workbook (first worksheet, header row) or a UTF-8 .csv
file**“. Формата качва файла през `POST /api/upload/image` — качването за картинки (вероятната причина).

**Пробвани пътища (2026-11-27, 1.0.36):**
1. Reservations › Excel import → Create → наш CSV (UTF-8, после UTF-8 с BOM) → Validate — не се чете (два пъти).
2. Reservations › Add new ▾ › Import reservations — води към същата страница; същото качване.
3. Експорт → внос: Reservations › Export › XLSX не дава файл (QA-544 — POST /api/template 404), така че собственият експорт не
   може да се внесе.

**Как се възпроизвежда**

1. Администратор на QA Automation → Reservations › Excel import → „Create a new reservation import“.
2. Сваля се CSV template от страницата на кой да е внос; попълва се един ред с наша обява и бъдещи дати; файлът се качва → Save.
3. На страницата на вноса → Validate → „The file could not be read …“.
