# QA-538 · api-probe — the server accepts EMPTY records the forms refuse: guest, cancellation policy, building, FAQ, guidebook template, unit, link, fee item

- Версия на приложението: **1.0.31** · Акаунт: QA Automation · Намерен в пуска api-probe-2026-11-26
- Спек: `tests/e2e/api-probe.spec.ts` — Проба през API преди кода на група 1 (празно създаване; всеки приет запис е изтрит веднага)
- Папка на пуска: [reports/test-scenarios/forms-map.md](../../reports/test-scenarios/forms-map.md)

**Какво се обърка**

`POST /api/<запис>` с празно тяло `{}` като администратор на QA Automation (2026-11-26 ~16:10, версия 1.0.31) **се приема**
(200, `success: true`) за: `guest` (записан с име „Guest“), `listingPolicy`, `listingBuilding`, `listingFaq`,
`guidebookTemplate`, `listingUnit`, `listingLink` (записан с име „ → “) и `feeItem`. Формите в интерфейса за същите записи
отказват празен Save („Required field“ при First name, Name / Code, Building name, Question, Name / Template type, Listing /
Name, Link type / Direction / Parent / Child, …) — сървърът не проверява задължителните полета, които формата изисква; друг
клиент (API ключ, плъгин, асистентът) може да запише празни записи. Правилно отказани: `listing` (−346), `reservation`
(−651), `reservationAlteration` (−655), `vatRate` (−496).

**Как се възпроизвежда**

1. Вход през API като администратор на акаунт (`POST /api/user/login`).
2. `POST /api/listingBuilding` с тяло `{}` → 200, записът е създаден без име.
3. Същото за останалите изброени.

Всеки приет запис е изтрит веднага (DELETE → ok).
